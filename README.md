# mini-codex

一个最小可用的本地编码助手。零第三方依赖，只用 Node 自带的模块。

一句话说明它在干什么：**给一个只会说话、还会失忆的大模型配一双手**——
模型负责想下一步做什么，程序负责真的去读文件、改文件、跑命令，然后把结果递回去，
这样一圈一圈转，直到任务做完。

---

## 一、最快上手：开网页界面

```sh
cd ~/Desktop/mini-codex
./start.command          # 或者在终端执行 node bin/mini-codex.js --web
```

浏览器会自动打开 `http://127.0.0.1:3333`。

第一次用，点右上角「设置」，把模型密钥填进去保存即可（密钥存在本机的 `config.json` 里，权限 600，只有你自己能读）。
之后在底部输入框里说人话就行，例如：

```
帮我在这个目录里建一个 hello.js，运行后打印当天日期
```

右侧会实时显示它每一步调用了什么工具；需要改动文件或跑命令时，右侧会弹出确认卡片，点「允许」才执行。

---

## 二、你需要准备什么

1. **电脑上有 Node 18 或更新版本**。终端执行 `node -v` 能看到 `v18` 以上即可。
2. **一个模型接口的密钥**。任何兼容 OpenAI 接口的服务都可以（OpenAI、DeepSeek、通义、月之暗面、本地 Ollama 等）。

密钥有两种放法，二选一：

- 网页里填（推荐，省事）：启动后点「设置」。
- 环境变量（适合命令行党）：
  ```sh
  export MINI_CODEX_API_KEY="你的密钥"
  ```
  想每次开终端都生效，把这行加到 `~/.zshrc` 末尾。

## 三、命令行用法

```sh
# 打开网页界面
node bin/mini-codex.js --web

# 命令行对话模式
node bin/mini-codex.js

# 直接干一件活，干完退出
node bin/mini-codex.js -t "把这个项目里的 TODO 注释列出来"

# 只看不改，最安全
node bin/mini-codex.js --readonly -t "解释一下 src 目录的结构"

# 接上上次的会话继续
node bin/mini-codex.js --resume

# 边想边打（流式输出）
node bin/mini-codex.js --stream

# 全自动，不再逐条问你要不要执行
node bin/mini-codex.js -y

# 只检查配置对不对，不联网不花钱
node bin/mini-codex.js --dry-run
```

对话模式里输入 `exit` 退出，`/reset` 清空上下文。

## 四、权限档位（重要）

它有能力改你的文件、跑你的命令，所以默认是**保守**的。

| 档位 | 怎么开 | 行为 |
| --- | --- | --- |
| 只读 | `--readonly`，或网页里选 readonly | 只能看，任何写文件和动手命令都被拒 |
| 询问（默认） | 不加参数 | 只有纯查看类命令（ls/cat/git status 等）直接跑，改文件和其他命令都要先问你 |
| 全自动 | `-y`，或网页里选 auto | 不再询问，危险命令仍会被硬拦 |

不管哪一档，下面这些都会被**直接拦死**，不给商量的余地：
递归强删、提权、格式化磁盘、关机重启、强推远端、硬回退、下载即执行等。

另外，所有文件操作都被限制在你指定的项目目录内，`../` 出去或写绝对路径都会被拒。
只读模式下的命令还额外禁止换行拼接、反引号、`$()`、管道和重定向，防止用 `ls | rm` 这类写法绕过。

## 五、它会用哪些工具

| 工具 | 用途 |
| --- | --- |
| `read_file` | 按行读文件，带行号，支持分页 |
| `edit_file` | 精确替换一小段，改动最小（推荐） |
| `write_file` | 整文件写入（新建文件或很短的配置） |
| `list_dir` | 列目录，自动跳过 node_modules 等 |
| `grep` | 按正则找代码、找报错 |
| `move_file` | 移动或重命名，目标已存在会拒绝 |
| `delete_file` | 删单个文件或空目录，非空目录拒绝 |
| `git_info` | 看 git 状态、提交历史、差异（只读） |
| `run_shell` | 跑测试、构建等命令 |
| `todo_write` | 记待办清单，长任务不跑偏 |
| `fetch_url` | 抓公网网页或接口（需打开联网开关） |
| `web_search` | 上网搜索，依次试 DuckDuckGo 与必应（需打开联网开关） |
| `open_item` | 用默认程序打开文件、文件夹或网址（需打开桌面开关） |
| `screenshot` | 截屏存到项目内（需打开桌面开关 + 系统屏幕录制权限） |
| `clipboard` | 读写系统剪贴板（需打开桌面开关） |
| `notify` | 发系统通知（需打开桌面开关） |
| `applescript` | 跑 AppleScript 控制系统（需打开桌面开关 + 辅助功能权限） |

## 六、联网与桌面操作

这两类能力会伸到项目目录外面去，所以**默认关闭**，要用的时候显式打开。

网页界面：右上角「设置」→「扩展能力」里勾上「允许联网」「允许操作桌面」，保存即可。
命令行：加 `--allow-network` / `--allow-desktop`，或者在 `config.json` 里写 `"allowNetwork": true`。

打开之后并不是无限制：

- 「询问」档下，每一次联网或桌面动作仍会先弹一张卡片等你点允许；「全自动」档才不打断你。
- 只读档下这两类操作一律拒绝。
- 联网只允许公网 http/https。本机、127.0.0.1、192.168.x、10.x、172.16-31.x、`.local`、`.internal` 全部被拦，防止模型借抓网页去扫你的内网或路由器。
- `open_item` 只能打开项目目录内的文件，或公网网址。
- `applescript` 里不许出现 `do shell script`（那等于绕开审批跑命令），要跑命令请走 `run_shell`，它有自己的审批。

首次使用可能需要在系统里授权，一次就够：

- 截屏：系统设置 → 隐私与安全性 → 屏幕录制，勾上你用的终端。
- AppleScript 模拟按键：隐私与安全性 → 辅助功能，勾上终端。
- 没授权时工具会返回明确的提示，不会静默失败。

## 六、终端接入与镜像窗口

`terminal` 工具接的不是"每条命令一个新进程"，而是一个**长期活着的登录 shell**：

- 用 `zsh -il` 启动，会读你的 `~/.zprofile` 和 `~/.zshrc`，所以 PATH、别名、nvm 全和你自己开的终端一致。
- `cd`、`export`、激活虚拟环境、nvm 切换都会留下来——下一条命令接着上一条的状态继续。
- 返回里会带上退出码和当前目录，模型知道自己在哪儿。
- 想要干净重来，给 `reset: true` 会重开一个会话。

和它并列的还有 `run_shell`：那个才是"一次一条、跑完即忘"，适合构建、测试这类互不影响的命令。

**镜像窗口**：在设置里打开「镜像到终端窗口」后，agent 每执行一条命令，都会实时显示在一个新弹出的 Terminal 窗口里，
方便你盯着它干了什么。这里只显示、不重复执行——窗口里跑的是 `tail -f` 盯着项目内 `.mini-codex/mirror.log`。
如果用别的方式往终端里直接塞命令，那条命令会被执行第二遍，这正是没有采用那种做法的原因。

已知限制：这个会话没有分配 pty，所以 vim、top 这类全屏程序画不出界面；交互式确认（比如 `npm init` 的问答）也跑不了。
需要这类操作，用桌面能力里的 `applescript` 让真实 Terminal 去做。

## 七、目录结构

```
mini-codex/
├── start.command         双击启动网页界面（macOS）
├── bin/mini-codex.js     命令行入口
├── public/               网页界面（零依赖，纯原生）
│   ├── index.html
│   ├── style.css
│   └── app.js
├── src/
│   ├── main.js           参数解析、打印、问确认、启动服务
│   ├── server.js         本地 Web 服务与审批通道
│   ├── loop.js           主循环（心脏）：问模型 → 执行工具 → 回填结果
│   ├── model.js          模型接口，支持流式输出
│   ├── router.js         模型路由：简单任务用小模型
│   ├── tools.js          工具注册表与十个内置工具
│   ├── context.js        上下文整理：截断与压缩
│   ├── prompt.js         系统提示词，三段式
│   ├── safety.js         路径校验、命令黑名单、权限档位
│   ├── settings.js       网页设置读写
│   ├── resume.js         会话续跑摘要
│   ├── config.js         配置读取
│   └── session.js        会话日志（.mini-codex/sessions/）
├── tests/                离线测试，不联网
└── config.example.json   配置示例，复制成 config.json 后修改
```

## 七、常见问题

**它说找不到密钥？**
点网页右上角「设置」填一次；或者在终端执行 `echo $MINI_CODEX_API_KEY` 确认环境变量设好了。

**想换模型或接口地址？**
网页「设置」里直接改，存的是项目内的 `config.json`。命令行参数 `--model`、`--base-url` 优先级更高。

**为什么有时候回答得特别快？**
配置了快速模型后，短问答会自动走小模型省钱：一句话的简单问题走快速模型，涉及改代码、查报错就走主力模型。在 `config.json` 里加 `"fastModel": "某个便宜模型"` 即开启。

**它改错了东西怎么办？**
它不会自动备份，但改动都在你的项目里。用 `git status` 看动了哪些文件，`git checkout` 回滚。建议在干净的 git 仓库里用它。

**会不会很贵？**
费用按收发的文字量算。这个程序已经做了三件事控成本：工具的冗长输出自动截断，跑太久自动压缩历史，简单问答自动路由到小模型。另外它有轮数上限（默认 25 轮），不会无限转圈。

**跑到一半卡住了？**
按 Ctrl+C 停。日志在项目的 `.mini-codex/sessions/` 目录下，
`node bin/mini-codex.js --list-sessions` 列出，`--replay 文件路径` 回看发生了什么。
想接着上次继续，用 `node bin/mini-codex.js --resume`。

**怎么确认这个程序本身没坏？**
```sh
cd ~/Desktop/mini-codex
node tests/offline.test.js && node tests/features.test.js
```
两批共 28 项测试全绿，说明主循环、工具、安全拦截、上下文压缩、模型路由、Web 接口都正常。测试用假模型，不联网不花钱。

## 八、目前还没做的
